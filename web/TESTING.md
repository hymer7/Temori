# Temori 手动验收清单

用三个不同邮箱的测试账号：群主、普通成员、群主指定的验收负责人。先在本地验证，再在部署后的网址重复关键路径。每项仅在实际功能可用时勾选。

## 账号、群组与隐私

- [ ] 三个账号都能收到一次性验证码，凭验证码登录；退出后不能继续访问需登录的页面。
- [ ] 群主创建群组后获得群号；成员能按群号搜索并申请加入，审批前不能进入群组。
- [ ] 群主批准后，成员能看到群组、群聊和任务；非成员和已退出账号不能读取群聊、任务、Issue、成果或附件，即使直接打开其网址。
- [ ] 普通成员不能批准入群申请，也不能指定最终验收负责人。

## 简单大任务：跳过 Issue

- [ ] 普通成员能创建带说明、期限和参考文件的大任务，不创建 Issue 也能提交文字、链接或文件作为成果。
- [ ] 群主可以要求修改；提交人再次提交后，旧版本和对应意见仍可查看。
- [ ] 带文件的新版本在上传完成前保持草稿，验收人看不到通过按钮；上传失败时可以补传并发布，附件没有丢失。
- [ ] 未指定验收负责人时，只有群主能通过最终成果；群主指定负责人后，只有当前有验收权限的人能通过。
- [ ] 最终验收通过后，能按需要记录对外交付信息并完成归档。

## 复杂大任务：Issue 与审阅

- [ ] 成员能创建多个 Issue，记录负责人、期限与讨论；讨论型 Issue 可记录结论后关闭。
- [ ] 普通成员新建的 Issue 默认为可选；只有任务协调人能把它设为必需。
- [ ] 成果能关联一个或多个 Issue；指定审阅人能对某一版本评论、要求修改或通过。
- [ ] 同一个工作型 Issue 只能关联一份成果；要求修改后沿用该成果提交新版本。
- [ ] 退回后再次提交会形成新版本，旧版本和评论仍可查看；未指定的成员不能通过 Issue 成果。
- [ ] 必需的 Issue 处理完后，任务负责人能汇总并提交最终成果；最终验收仍由群主或其指定负责人完成。

## 线上试用

- [ ] 部署网址可由另一台设备打开，邮件验证码登录及回跳正常，页面刷新后数据仍在。
- [ ] 上传的文件仅允许所属群组成员访问；数据库与文件访问规则在服务端生效。
- [ ] 用一组三人测试账号完整走通两条路径，记录失败步骤、浏览器和复现方式。
