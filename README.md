# Temori

一个面向大学生小组的协作产品。第一阶段聚焦课程小组作业：把组内沟通、任务分工、成果提交和审阅放在同一个项目中。竞赛团队和志愿活动是后续验证的场景。

## 想解决的问题

学生常在微信里组队做事，但任务、文件和反馈散落在聊天记录中。成员不容易看清谁负责什么、哪个成果是最新版、修改意见是否已经处理，以及任务是否真正完成。

## 核心流程

1. 组长创建项目并邀请成员。
2. 成员在项目内聊天、确定任务负责人和截止时间。
3. 负责人提交文字、链接或文件作为成果，系统保存每次提交的版本。
4. 审阅人在对应版本下评论，并选择「要求修改」或「通过」。
5. 被退回后负责人提交新版本；旧版本和讨论仍可追溯。
6. 审阅通过后，任务才进入完成状态；项目结束后可归档。

独立的组内聊天和完整的成果审阅都是首版必需能力。这里的“审阅”借鉴 GitHub 的协作流程，但成果不限于代码，也包括文档、PPT、图片、PDF、链接和志愿服务证明。

## 当前状态

项目处于需求验证与原型设计阶段。技术栈和具体界面尚未确定；先用真实学生小组验证核心流程，再做实现选择。
